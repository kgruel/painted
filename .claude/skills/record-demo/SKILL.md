# Record a demo

`vhs` drives a headless terminal from a script (a "tape") and writes frames.
`ffmpeg` turns those frames into the artifact. Both are already installed
(`brew install charmbracelet/tap/vhs ffmpeg` if not).

**This is for sharing motion — a PR, an issue, a review.** It is not the
docs pipeline: the committed panels on the docs site are real `render_html`
output regenerated by `./dev panels`, gated by the `outputgen` tier. A video
of a demo is never a substitute for that, and recordings are **not committed**
— write them to a scratch directory and hand over the path.

## The tape

```
Output frames/                     # NOT out.mp4 — see the 25fps trap below
Set Shell zsh
Set FontSize 14
Set Width 700
Set Height 620
Set Padding 14
Set Framerate 60
Hide
Type "cd /Users/kaygee/Code/painted" Enter
Type "clear" Enter
Show
Type "uv run demos/showcase/raymarch.py --live" Enter
Sleep 34s
```

```bash
cd <scratch-dir> && vhs demo.tape
ffmpeg -framerate 60 -i "frames/frame-text-%05d.png" \
  -vf "pad=ceil(iw/2)*2:ceil(ih/2)*2" \
  -c:v libx264 -pix_fmt yuv420p -crf 20 -movflags +faststart out.mp4
```

`frames/` holds `frame-text-*` and `frame-cursor-*`; use `frame-text-*` unless
you want the cursor drawn.

## The four traps

1. **`Output out.mp4` is hard-capped at 25fps**, whatever `Set Framerate`
   says — vhs re-encodes. A 30fps demo silently loses frames. Render to
   `frames/` and encode yourself, as above. `Output out.gif` respects the
   framerate but files run ~10x bigger (11MB vs 1MB for 20s).

2. **libx264 needs even dimensions and vhs frames are often odd** (a 700px
   window yielded 639px content). Without the `pad` filter above, ffmpeg dies
   with "Error while opening encoder — maybe incorrect parameters such as
   bit_rate, rate, width or height", which names everything except the cause.

3. **`Height` too small fails or clips**, and the error is the same unhelpful
   "Conversion failed". Budget `rows x FontSize x 1.45 + 2 x Padding`; a
   24-row demo at FontSize 14 needs ~620px. `Width`/`Height` are the *window*,
   not the content.

4. **vhs is a TTY, so AUTO resolves to LIVE** for any demo declaring
   `fetch_stream` (docs/MODE_RESOLUTION.md). A bare invocation records the
   animation — usually what you want. For a still, pass `--static`; `--frame N`
   only affects static output, since live always starts at frame 0. `-q`,
   `--json`, and `--plain` also collapse to STATIC.

## Framing a showcase demo

Showcase demos render a 64-cell-wide grid plus a border (66 cells). At
FontSize 14 that wants `Width 700`. Oversizing wastes canvas — the demo sizes
to the terminal at launch, so a 1400px window leaves two thirds of the frame
empty rather than drawing bigger.

Showcase streams run `_MAX_FRAMES = 900` at 30fps: ~30s of animation, then a
final settled frame. `Sleep 34s` captures the settle (usually the payoff shot).
`Ctrl+C` mid-run cuts it short instead.

## Stills and measurement

```bash
# a frame at t=30s, and the last frame
ffmpeg -ss 30 -i out.mp4 -frames:v 1 shot.png
ffmpeg -sseof -1 -i out.mp4 -frames:v 1 final.png
```

**To measure the delivered frame rate, read the demo's own counter — don't
trust `mpdecimate`.** Pull a still at two timestamps, read the frame number
off each, and divide the difference by the elapsed seconds. Most showcase
demos put the counter in their census row, which is exactly what it's for.

```bash
for t in 8 18; do ffmpeg -ss $t -i out.mp4 -frames:v 1 t$t.png; done   # then read them
```

`mpdecimate` counting "unique" frames looks like a cleaner method and is a
trap: it reports **above** the true rate, because a cost-meter tick or a
spinner step makes an otherwise-identical frame count as distinct, and the
answer moves with the filter's sensitivity. On the same raymarch recording
whose counter proves 28.2fps, the default filter says 32.8 and
`hi=200:lo=100:frac=0.001` says 57.8 — the latter just recovering the
container rate. Use it for "is anything moving at all", never for a number
you report.

Encode at 60 so a ~30fps source is oversampled and its cadence preserved, and
never report the container's rate as the demo's.
