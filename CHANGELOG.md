# Changelog

All notable changes to painted are documented here. This project adheres to
[Semantic Versioning](https://semver.org/); pre-1.0, minor versions may carry
breaking changes.

## [0.3.1] — 2026-06-15

A point release widening one contract and adding a batch of consumer-driven primitives, each landed where a downstream consumer (the loops rebuild, and the siftd terminal-UI refresh) reached a real call-site. `record_line`/`record_line_composed` now accept `width=None` for natural sizing; `table()` gains a controlled-shrink overflow mode and per-column ellipsis markers; a new `callout` primitive renders severity-tagged messages; the `Palette` can now own body text (and an optional canvas); the truncation marker degrades to ASCII via a new `IconSet` slot; a `rule()` divider plus rank-tier glyphs round out the gutter vocabulary; multi-style `Line`s gain a `wrap()` reflow rung to match single-style `Block.text`; and the wcwidth-aware `display_width` measurement graduates from a private module to the stable `painted.core` surface. All backward-compatible — defaults are byte-identical to today, and `width=int`/existing callers render unchanged.

### Added

- **`display_width` graduated to the stable surface.** The wcwidth-aware display-column measurement (`display_width(text) -> int`) is now exported from `painted.core` (semver-stable), promoted from the private `painted.core._text_width`. It is painted's foundational width primitive — "a block's display width is not `len()`" — and a consumer laying out its own content had no public way to measure columns; the siftd terminal-UI refresh reached into the private module from four call-sites. The function is unchanged (falls back to `len()` for non-printable strings); only its home becomes public. `core`-only on purpose — measurement is a primitive and `core` is its honest home, not a second `views` re-export to owe forever.
- **`Line.wrap()` — multi-style reflow.** New `Line.wrap(width, *, wrap=Wrap.WORD) -> Block` reflows a multi-style `Line` across rows, the multi-line generalization of `Line.to_block` (which is single-line `Wrap.NONE`). It restores the rung the disclosure ladder was missing for styled text: `str` already had `Block.text(..., wrap=…)`, but `Line` — the mixed-style primitive — only had single-line `truncate`/`to_block`, so the moment text carried a second style, reflow vanished and the caller fell to hand-laying cells. `wrap` mirrors `Block.text`'s four `Wrap` modes exactly; each span's style merges onto the `Line` style and rides with its characters across line breaks; pad cells and the ELLIPSIS marker inherit the `Line`'s base style. Under the hood the wrap engine is now unified — `_char_wrap`/`_word_wrap` operate on a styled-char stream and the `str` path is the uniform-style adapter over it, so single-style output is byte-identical to before (source spaces preserved, break space right-trimmed).
- **`Palette.text`/`surface` — substrate ownership.** A `Palette` can now own "body text" (and optionally a base canvas), not just the five semantic roles. The new optional `Palette.text`/`surface` Styles supply a default `fg`/`bg` wherever a cell's `Style` leaves `fg`/`bg` unset; an explicit `fg`/`bg` on the cell always wins. Both default to `None` — byte-identical to today's terminal-default behavior. Resolution is a single pure pass (`Palette.resolve_style`, layering `text` under the cell style and `surface` as the base `bg`) applied at the writer's two SGR-emission sites; the `Style → SGR` conversion stays pure. Previously a theme could color only the five roles, so it could not make plain text theme-wide.
- **`rule()` divider primitive.** New public `rule(width, *, char=None, style=None) -> Block` on `painted.core.compose` renders a horizontal divider: one row of `char` exactly `width` columns wide, honoring the width contract. `char=None` reads the ambient `IconSet.rule` (new slot, `─` / ASCII `-`) so it degrades like every other glyph; `style=None` reads `current_palette().muted`. Exported from `painted` and `painted.core` (semver-stable). Replaces the hand-drawn `char * n` + ASCII-fallback idiom consumers were repeating.
- **`IconSet.ellipsis` slot — ASCII-degradable truncation marker.** The truncation marker is now a glyph slot (`…` / `ASCII_ICONS` `...`) rather than a hardcoded literal. Every marker site routes through the ambient icon: `compose.truncate` and `_text_width.truncate_ellipsis` default `ellipsis=None` → `current_icons().ellipsis`; `block.py`'s `Wrap.ELLIPSIS` reads the ambient marker and reserves its full display width (no longer assuming a one-column ellipsis, so a multi-column `...` correctly cuts content to make room); the table per-column ellipsis path inherits it. Under `use_icons(ASCII_ICONS)` truncation degrades to `...` everywhere, and a strict-ASCII stream no longer raises `UnicodeEncodeError` mid-render on the `…` codepoint. Defaults preserve Unicode behavior exactly.
- **`IconSet` rank-tier glyphs.** A rank ladder for attention/relevance rails — `rank_top` `◆` / `rank_mid` `│` / `rank_tail` `·` (ASCII `*` / `|` / `.`). `views`' `apply_attention` now reads its high-rank marker and collapsed-line dot from the ambient `IconSet` instead of hardcoding `◆`/`·`, so they degrade with every other glyph.
- **`table()` `Overflow.FIT` mode + per-column ellipsis.** `Overflow.FIT` is a controlled-shrink policy (the `resolve_column_widths` follow-up): `Fill` columns size to content and never stretch into slack; when over budget they shrink toward their `min_width` floors to absorb the overflow; and if the non-`Fill` columns alone exceed the budget the table overflows at natural width rather than clipping — so no column or value is ever silently dropped. `Overflow.CLIP` (default) keeps the historical right-clip. `Column.ellipsis=True` adds a `…` marker on truncation, with `ellipsis_side` choosing which end survives: `Align.END` keeps the head (`"long descrip…"`), `Align.START` keeps the tail (`"…Code/siftd"`, so a path leaf survives), backed by a right-anchored `_truncate_keep_end`. `ellipsis=False` keeps the historical marker-less cut. `Overflow` is exported from `painted.views`.
- **`callout` message primitive.** `painted.views.callout(subject, *, severity, detail, hint, box, width) -> Block` renders a severity-tagged message line: `severity` (`"success"`/`"info"`/`"warning"`/`"error"`) drives both the glyph (ambient `IconSet`) and the color (ambient `Palette` role), with an optional muted `detail` line, an optional muted `↳ hint` next-step line, and an optional bordered panel. Fills the message/callout gap alongside `table`/`record_line`/`progress`.
- **`IconSet` severity ladder.** A coherent 4-level severity ladder (`ok ✓` / `info ℹ` / `warn ⚠` / `error ✗`) plus a `↳` hint arrow, each with aligned single-char ASCII (`+` / `i` / `!` / `x` / `->`) so callouts degrade canonically under `use_icons(ASCII_ICONS)`. Distinct from the generic `check`/`cross` pass-fail markers.

### Changed

- **`record_line`/`record_line_composed` accept `width=None` (natural sizing).** Previously `width` was a mandatory `int` and `record_line(width=None)` raised `TypeError` (it computed `width - meta_width`). `None` now selects natural sizing — no padding, no truncation, the record keeps its intrinsic width — exactly the omit-width escape that `Block.text(text, style)` already documents. `record_line` was the outlier that didn't honor it. At every zoom, content (default summary, `PayloadLens` strings/Blocks, secondary fields, FULL field lines) renders untruncated; `record_line_composed` propagates `None` to the inner line and still applies gutter (height-based) and attention markers. `apply_attention`'s `width` is correspondingly `int | None`. No public-API names added or removed; `width=int` callers render identically.

## [0.3.0] — 2026-06-15

A focused minor: three additive primitives for fitting content into width budgets and routing a CLI's primary noun, each landed where a downstream consumer (the loops rebuild onto painted) reached a real call-site for it. `table()` columns gain CSS-grid-style track sizing; `budget_fields` allocates labelled fields into a trailing slot with shrink-then-drop; and `run_app` learns a primary-noun fallthrough. All backward-compatible — `width=int` table callers and existing `run_app` apps are unaffected.

### Added

- **Responsive table column widths.** `Column.width` is now a track-sizing function rather than a bare `int`: `AUTO` sizes a column to its natural (wcwidth-aware) content width, `Fill(weight)` shares whatever budget remains after the other columns and splits it among flex columns by weight, and a plain `int` stays a fixed width — with `Column.min_width`/`max_width` clamping any result. `table()` runs the resolution whenever it is given a `width` budget; without one, columns size to their content as before. `width=int` (and untyped) callers are unaffected; `width` now defaults to `AUTO`. `AUTO` and `Fill` are exported from `painted.views` (semver-stable); the `resolve_column_widths` pre-pass stays submodule-private until linked-width sharing lands.
- **`run_app` primary-noun fallthrough via `default=`.** `run_app(..., default=AppCommand)` (and the `AppRunner.default` field) routes an unmatched non-flag `argv[0]` to a default command — the `app <token>` shorthand (e.g. `loops <vertex>` ⇒ `read <vertex>`) lifted into the framework instead of a hand-rolled pre-router in front of the runner. Opt-in: omitted, an unmatched token is an "Unknown command" error exactly as before, and a leading flag (`-h`/`--help`) still routes to top-level help, never the default. Matched commands receive `argv[1:]` (the name is consumed); the default receives the full `argv` (the token is positional data). Evolving `painted.cli` surface.
- **`budget_fields` field-budget allocator.** New public `budget_fields(fields, width, *, min_field=12, sep=" · ") -> BudgetFit(text, dropped)` on `painted.core.compose` fits ordered labelled fields into a width budget for a trailing slot: it renders the longest contiguous prefix where each field either fits whole or truncates to at least `min_field` columns, accounts separator cost between kept fields, and reports the shed content as a column count for the caller's overflow hint (e.g. `[+Nc]`). Width is measured in display columns (wcwidth), so it budgets CJK and emoji correctly where a `len()`-based fit would not. It is the *shrink-then-drop* counterpart to the table's keep-all `resolve_column_widths` — a distinct allocation contract, sharing only separator accounting, not a reframing of one. Presentation stays with the caller: the overflow badge and any empty-field fallback are not painted's, so this is a pure character-budget contract with no `Style`. `budget_fields` and `BudgetFit` are exported from `painted` and `painted.core` (semver-stable).

## [0.2.0] — 2026-06-14

The framework release. v0.1.x shipped a terminal *renderer*; 0.2.0 grows the *CLI/disclosure framework* on top of it. The fidelity disclosure grammar lets an app declare its view layers (`Tag`), zoom spellings (`depth_aliases`), and density budgets and have the flags, help, and `Fidelity` compilation fall out of the declaration. Live delivery gains a tear-free alt-screen tier, the long-standing `run_app` multi-command dispatcher is dogfooded as painted's own front door and gains alias routing, and the doc-IR closes the publish trinity — terminal help, the new `painted docs` command, and the web docs site all project from one document tree.

### Added

- **Tag disclosure declarations.** Declare a named, toggleable view layer with `Tag(name, help, implied_at)` and pass it to `run_cli(tags=[...])`. One declaration generates the `--{name}` flag, its help entry under a "Layers" group, and its compilation into `Fidelity.visible`; `implied_at` turns the facet on implicitly at that depth and above (`-vv` ⇒ depth 3). Gate rendering with `ctx.fidelity.shows(name)`. Semantic-layer flags now stand on the same declarative footing as the `modes=` capability pattern, so apps no longer hand-roll a `fidelity_from_args` per tool.
- **Depth aliases for app-local zoom spellings.** `run_cli(depth_aliases={"brief": 0, "full": 3})` adds app-named spellings of the depth axis. Each alias generates a `--{name}` flag in the same mutually-exclusive group as `-q`/`-v` and sets depth directly. It is pure spelling: an alias to depth 0 implies `--static` exactly like `-q` because the runner checks the compiled `fidelity.depth`, not the flag, and the alias inherits any facet implications at its resolved depth.
- **`build_fidelity` escape hatch.** `run_cli(build_fidelity=fn)` runs a `(namespace, Fidelity) -> Fidelity` hook *after* tag, alias, and budget compilation, so the hook sees the fully compiled spec. It is the residue seam for disclosure logic the declarative grammar cannot express — for example, reading an env var as a baseline depth.
- **Declaration collision and validity checks at parser construction.** Declared tag and alias names are validated when the parser is built, not at runtime: a name must be lowercase kebab-case, must not collide with a framework flag (`--quiet`, `--json`, `--max-chars`, …), and must not collide with another declaration (tag↔tag, tag↔alias); a negative alias depth also raises. Framework names are reserved regardless of `modes=`/`budgets=` filtering, and a custom `add_args` arg can no longer silently land on a declared dest — it raises a construction-time `ValueError`.
- **`Fidelity.implied_visible` and `help_doc` are public on `painted.cli`.** Two new names join the evolving `painted.cli` surface: `implied_visible(tags, depth)` (the shared depth→facet implication law, so non-CLI harnesses resolve a depth into the same visible set the flag compiler produces) and `help_doc(runner)` (the doc-IR `Doc` the help screen is now built from).
- **`painted docs` command.** A terminal front door that renders authored documentation pages as live output: `painted docs` lists pages, `painted docs <name>` renders one. Pages dispatch through `run_cli`, so `-v`/`-vv` thread to `Fidelity.depth` and tagged layers surface as declared flags — `--rationale` appears exactly on pages that have rationale-tagged nodes. Ships one page (primitives), authored as a node tree with a live `Figure` specimen (doc == demo).
- **Two-tier live delivery via `run_cli(live_delivery=)`.** `run_cli` now selects between two live tiers with `live_delivery="inplace"|"surface"` (default `"inplace"`, back-compatible). The `"surface"` tier hosts `fetch_stream` on an alt-screen `StreamSurface` that diffs absolute per-cell — structurally immune to the scroll-tearing relative cursor addressing suffers — then deposits the final frame to the normal screen on exit; the in-place tier stays ephemeral liveness in scrollback. An invalid value raises at construction. With `"surface"`, `-i` and `--live` converge onto the same surface.
- **Opt-in delivery-cost gauge via `run_cli(live_meter=)`.** `run_cli(live_meter=True)` lets the framework gauge its own live delivery: both live tiers measure render+write cost per frame and dress each delivered frame with a `cost_meter` row. The budget is measured, not declared — the median inter-frame period — so the gauge self-calibrates to any cadence. Opt-in (default `False`) so existing `fetch_stream` apps' output never changes unbidden; opted-out runs pay nothing, and pipes/static output are never dressed.
- **`cost_meter` views component.** `cost_meter(samples_ms, width, *, budget_ms, label, palette)` joins the public `painted.views` surface: a single-row gauge that renders observed per-frame costs against a time budget, returning `None` when nothing was observed so static output stays undressed. The role encodes headroom — success under 50% of budget, warning under 90%, error at or beyond — and the fixed-format cost plus padded sparkline hold row width stable so bordered windows never breathe.
- **`AppCommand.aliases` for multi-command apps.** `AppCommand` now takes an `aliases` tuple; dispatch routes on the command name or any of its aliases, and aliases surface in top-level help as a parenthesized suffix on the command row (e.g. "demos (alias: demo)", pluralized for multiple). Names and aliases share one dispatch namespace.
- **Construction-time validation of command names and aliases.** `AppRunner` now rejects ambiguous routing at construction: a command name declared by more than one command, an alias equal to its own command's name, the same alias listed twice on one command, an alias colliding with a command name, or an alias colliding with another command's alias all raise `ValueError`. Misconfiguration is caught at wiring time rather than silently shadowing at dispatch.
- **`fit_to_width` block primitive.** New public `fit_to_width(block, width)` realizes the width contract at the block level: truncate (with ellipsis) if wider, pad with spaces if narrower, identity if exact. Horizontal-only — it clips rather than reflows, so wrap content first to grow height instead.
- **`PAINTED_PALETTE` and `PAINTED_THEME` presets.** A vivid, truecolor-first palette and its matching theme ship as named presets alongside `DEFAULT`, `NORD`, and `MONO`. The name is the semver contract; the hex values are tunable. Both are exported from `painted` and `painted.views`.
- **`Palette.series` categorical ramp.** `Palette` gains a `series` field: a categorical (qualitative) ramp of Styles indexed by position, distinct from the five semantic roles, for visually separating N peers. `flame_lens` now consumes `current_palette().series`. Each preset defines its own ramp (`MONO` uses modifier-only styles, no hue); a custom `Palette` with no series gets the default red/yellow/green/cyan ramp.
- **Architecture guard `test_public_names_do_not_shadow_submodules`.** A static guard that prevents a public name equal to a submodule filename from being permanently shadowed by the module object once anything imports the submodule.
- **Internal: doc-IR document compositor (provisional, not yet public).** Adds the doc-IR — a fixed document node vocabulary (`Doc` root over a `Node` union of `Section`/`Prose`/`Defs`/`Items`/`Code`/`Figure`, with `Def` as a `Defs` entry) and `doc_lens`, the projector that lays a document out into a `Block`. Disclosure is governed by `Fidelity` via a per-node effective tier (`eff = depth - min_depth`, plus a tag check) that cascades through Sections, so list density expands without re-authoring content. Lives in `core/doc.py` as a peer of `compose.py` (moved there from `views/lens`) so it imports only `core`, but is deliberately held out of `painted.core.__all__` until the Inline-union and `Code(ref)` authoring seams settle.
- **Internal: dev/docs infrastructure.** The Astro docs site is folded into the monorepo at `web/` so one generator regenerates the in-repo docs and the external site's panels together and they cannot silently drift; `tools/outputgen.py` renders real painted Blocks to HTML/plain/JSON panels with a `./dev check` "Outputgen" tier gating committed output against a fresh render; `tools/doc_publish.py` adds `to_html`, a *tools-only* publisher that emits semantic HTML (`<section>`/`<h2>`/`<dl>`) from the same doc node tree the terminal lens renders, sharing the one `visible_body`/`capped` disclosure walk so terminal and web cannot disclose differently. Backed by a docgen fragment/region engine (`./dev docs`), reference/landing specimen catalogs of real Block renders, the animated demo curriculum (rungs 1–6: plasma, fire, boids, lorenz, wireworld, raymarch), the full-ladder disclosure exemplar in `demos/patterns/fidelity.py`, and the stdlib-only `tools/term_probe.py` DEC 2026 diagnostic. `web/`, `tools/`, `demos/`, and `docs/` are dev infrastructure only — the wheel ships `src/painted` and stays zero-dependency.

### Changed

- **Width is an exact contract.** A passed `width` is now exact everywhere blocks are produced — blocks, lenses, records, and composers all satisfy `block.width == width`: short content is padded, too-wide content is clipped, never overflowing horizontally. Pass `wrap=Wrap.CHAR`/`Wrap.WORD` to reflow into more rows instead of clipping; omit `width` for natural content sizing. Exactness lets callers carve a width budget into pieces that tile with no gap or overflow at any terminal size.
- **`Fidelity` is the canonical compiled disclosure spec.** `Fidelity` is the single compiled disclosure spec — `depth` (anonymous detail), `visible` (named facets resolved at compile time), `chars`/`lines` (density budgets) — travelling whole through `CliContext.fidelity`. Renderers beyond rung 1 receive the spec intact rather than exploded into kwargs; `ctx.zoom` is the rung-1 porthole. Docstrings reframe the prior "three-axis" story as the honest disclosure ladder.
- **Help rendering dissolved onto the doc lens.** The CLI help screen is now authored as a doc-IR `Doc` and projected through `doc_lens` rather than a bespoke renderer. The help tiers (compact names through expanded group/flag detail) fall out of the doc-IR's effective-tier cascade. Help keeps the full term spelling intact (no lossy flag downcast) and respects Format — the writer strips styles for plain output and emits JSON for `--json` — instead of a one-off ansi toggle. User-visible help layout is materially the same; the authoring DTO (`HelpArg`) and the arg pre-scan (`scan_help_args`) are unchanged.
- **Layers help group leads and stays at minimal verbosity.** Declared Tags render first among the framework help groups and at MINIMAL depth, instead of collapsing with Zoom/Mode/Format when command args lead. Tags are app-declared vocabulary, not universal grammar, so their descriptions show exactly where they are least guessable. Applies in both `run_cli` help and subcommand help.
- **`run_cli` validates `live_delivery` at construction.** Passing a `live_delivery` value outside `{"inplace", "surface"}` now raises `ValueError` at `CliRunner` construction instead of silently degrading to in-place delivery, matching the framework's other declaration-collision checks.
- **Single-write block delivery for `print_block`.** `print_block` and `InPlaceRenderer` now build each frame as one ANSI string (via the shared `render_block_ansi`/`render_row_ansi` builders) and emit it with a single write followed by one flush, instead of flushing per line — removing the mid-frame buffer boundaries that let terminals catch partially drawn frames.
- **Halved `painted.tui` import cost.** `asyncio` (the bulk of the `painted.tui` eager import chain) is now imported lazily inside `Surface.run`, so importing `Surface` — for `TestSurface`, type access, or subclassing — no longer pays for it; only a running event loop does.
- **Scroll-optimization env var renamed to `PAINTED_SCROLL_OPTIM`.** The Surface scroll-optimization toggle now reads the `PAINTED_SCROLL_OPTIM` environment variable, replacing the stale pre-rename `FIDELIS_SCROLL_OPTIM` name.
- **Palette is the single source of theme colors.** Theme presets now compose palette presets instead of redefining colors inline, removing the drift vector that let theme colors desync from the palette (notably the series ramp). A custom `Palette()` with no explicit series now receives the default red/yellow/green/cyan ramp rather than colors derived from its semantic roles.
- **Internal: framework dogfooding and dev infrastructure.** painted's own front door (`src/painted/__main__.py`) was migrated from a hand-rolled multi-command dispatcher to a `run_app` + `AppCommand` table (with `demo` an alias of `demos`), so the CLI drives the same framework painted ships; the README/consumer guide were rewritten to document the disclosure-grammar declaration, the live-delivery ladder, the `run_app` row, and the `painted.cli`/`painted.tui` stability tiers; the test architecture was overhauled by axis into a 10-tier fast-fail gate (arch, lint, smoke, unit, property, appearance, integration, cohesion, outputgen, docs); the pattern demos converged on the `>=` zoom-threshold idiom; the cli→library import allowlist was formalized as `_CLI_SEAMS` with a two-entry "re-layer, never relax" tripwire; and the depth→facet implication law was extracted so non-CLI harnesses and the flag compiler can't diverge. Dev/dogfood/docs only; not shipped in the wheel.

### Removed (breaking)

- **Deep submodule import paths under `painted.views`.** Importing implementation modules directly no longer resolves: `painted.views.profile` and `painted.views.components.{spinner, table, list_view, text_input, data_explorer, sparkline}` were renamed to private underscore-prefixed modules. Public names are unchanged — import them from the `painted.views` facade (the documented path). This closes a latent import-order trap where a public name equal to a submodule filename was permanently shadowed by the module object once anything imported the submodule.
- **`Depth` alias for `Zoom`.** The `Depth` name (an alias of `Zoom`) is removed from `core/fidelity.py` and every export surface. `Zoom` is the one public name for the rung-1 axis, and `ctx.zoom` is the porthole onto `ctx.fidelity` — blessed permanently, two-sidedly clamped to the enum.
- **Density budget flags are opt-in.** `--max-chars`/`--max-lines` now exist only when an app declares `budgets=True` on `run_cli`/`add_cli_args`; the default flipped from `True` to `False`. Previously the flags were added unconditionally yet no `run_cli` app honored them — a dead flag surface. Read `ctx.fidelity.chars`/`ctx.fidelity.lines` after declaring the capability.
- **Generic `--show TAG` escape in the docs CLI.** The docs CLI's `--show TAG` flag is retired in favor of the declaration grammar: `run_doc` enumerates the built doc's node tags into Tag declarations, so a flag like `--rationale` exists exactly on pages that have rationale nodes and appears in each page's Layers help. One spelling per facet. This also deletes the `add_args`/`build_fidelity` pair the docs CLI previously carried.
- **Public help-renderer DTOs and helpers.** `HelpData`, `HelpGroup`, `HelpFlag`, `render_help`, `build_help_data`, and the lossy `help_args_to_flags` bridge are deleted — subsumed by the doc-IR. `HelpData`/`HelpGroup`/`HelpFlag`/`render_help`/`help_args_to_flags` were exported from both `painted.__all__` and `painted.cli.__all__` at v0.1.8, so `from painted import HelpData` no longer resolves; this is allowed because `painted.cli` is the evolving (non-semver-stable) framework surface, but it is a public-name removal. `app_runner` now shares `run_cli`'s `framework_sections`/`command_defs` builders instead of its own parallel help construction. User-visible help behavior is preserved.
- **Bundled static docs site.** The previously bundled `site/` output is no longer tracked; the docs site lives in-repo at `web/` and is regenerated by `./dev panels` rather than shipped.

### Changed (breaking)

- **`big_text` FILLED renders from one 8×8 bitmap font at a selectable density.** The hand-encoded FILLED glyph tables are replaced by a single public-domain IBM PC 8×8 bitmap font plus a density packer, so `size` is a vertical density dial over one font rather than a second font: `size=1` is HALF (8×4 cells, the compact default), `size=2` is FULL (8×8 cells). Glyph width is now a constant 8 cells. Breaking: the `BIG_GLYPHS` value type changed to 8-int tuples and `size=1` output dimensions changed (width `5n-1` → `9n-1`), so downstream fixed layouts may shift. `BIG_GLYPHS` and `render_big` are in the semver-stable `painted.views.__all__`. OUTLINE is unchanged.

### Fixed

- **InPlaceRenderer flicker and blank-phase tearing.** `InPlaceRenderer` now emits each frame as one atomic write wrapped in DEC 2026 synchronized-output markers, overwrites rows in place with erase-to-EOL (CSI 0K) instead of blanking the whole region first, and row-diffs same-height frames so only changed rows are rewritten (unchanged rows become cursor hops). This eliminates the flicker and torn partial frames seen when a window is backgrounded; terminals that ignore the sync markers degrade cleanly.
- **Frame-time-compensated Surface pacing.** The Surface run loop slept a full frame period after each blocking render, so animating apps ran at roughly render_time + period (~23fps under a 30fps cap). Pacing is now the pure function `frame_sleep(elapsed, fps_cap, active=)`, which sleeps only the remainder of the frame period, floored at `MIN_YIELD` — restoring the capped frame rate.
- **Surface restores the terminal when `run()` setup fails.** `Surface.run` entered the alt screen and hid the cursor before its try/finally, so an exception during sizing, user `layout()`, or signal-handler setup left the terminal wedged. Setup now runs inside the try, and the finally guards SIGWINCH removal for the not-yet-installed case, so the terminal is always restored.
- **Surface-path delivery errors honor the exit-code contract.** A delivery-level exception escaping the alt-screen `StreamSurface` path (terminal setup or sizing failure) is now translated to a stderr message and exit code 1 instead of leaking a traceback past `run_cli`'s documented `int` return contract. User fetch and render errors continue to map to exit 1 and 2 respectively.
- **Pause key in surface live delivery.** The old hand-rolled streaming handlers bound pause to `"space"` while the keyboard reports the spacebar as `" "`, so pause never fired. Converging the live tiers onto `StreamSurface` fixed it — the spacebar now toggles pause, which stops consuming the stream (nearly free).
- **`render_html` resolves named colors through painted's own color table.** `render_html` now maps a named color (e.g. `"red"`) to its painted ANSI-index RGB rather than passing the CSS keyword through, so HTML output matches what painted renders in the terminal (CSS keyword `"red"` is `#FF0000` but painted red is not).
- **Normal ANSI colors brightened for dark-background legibility.** The six normal ANSI colors (1–6) move from classic VGA half-intensity `0x80` to `0xC0` (192), matching modern terminals; normal red was below the WCAG 3:1 contrast floor on dark backgrounds. The RGB table is dual-use, so this brightens `render_html` and int-color display output and also shifts the truecolor-to-16 downsampling anchors. It stops at 192 (not xterm's 205) to avoid crushing dark midtones to black.
