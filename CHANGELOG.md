# Changelog

All notable changes to painted are documented here. This project adheres to
[Semantic Versioning](https://semver.org/); pre-1.0, minor versions may carry
breaking changes.

## [Unreleased]

The **renderer contract** (0.11, M4) — the framework-seam renderer boundary
`(data, fidelity, width) → Block`, ratified in `docs/RENDERER_CONTRACT_DESIGN.md`.
Landing in slices; this section accumulates until the cut.

### Added

- **`renderer=` — the renderer contract arrives at `run_cli`/`CliRunner`** (S1,
  `docs/RENDERER_CONTRACT_DESIGN.md` §§1, 3). A keyword-only parameter taking the
  `(data, fidelity, width) → Block` callable: the semantic renderer given only
  its three inputs — the domain state, the compiled `Fidelity` **intact** (never
  decomposed into loose kwargs), and the offered width. It sits beside legacy
  `render=` (the `(ctx, data)` callback), which keeps working unchanged through a
  deprecation window — no runtime warning in 0.11 (that gate opens at 0.12).
- **`Renderer` — the contract as a published type, in `painted.core`.** The
  render model's central unit joins the semver-stable core surface (guarded by
  `tests/unit/test_public_api.py`), beside the `Fidelity` spec it references — so
  the 0.13 host rung can run the same renderer through `Surface` without a
  `tui`→`cli` import. `painted.cli` re-exports it for convenience.
- **The width offer seam — `_offered_width`** (S2, `docs/RENDERER_CONTRACT_DESIGN.md`
  §§5–6). A `renderer=` is offered `ctx.width` under STATIC+TTY and `None`
  (natural sizing) under any non-TTY — never a fabricated column count for a
  pipe. Both live hosts (`InPlaceRenderer`, `StreamSurface`) re-offer the
  buffer's *current* geometry on every frame, so a mid-run resize re-enters the
  renderer as changed input rather than a once-captured detection-time width.
- **`ref_schemes=` — the framework-tier denotation declaration** (S4,
  `docs/RENDERER_CONTRACT_DESIGN.md` §7). Static (a tuple of `RefScheme`) or
  callable (`state -> tuple[RefScheme, ...]`, re-evaluated once per fetch
  event) forms install as a per-cycle bracket around fetch/render/flush: the
  prior ambient `use_refs` state is preserved and restored, and
  `ref_schemes=[]` disables ambient resolution for the run without leaking
  into the next one. A raising callable's exception enters the render-error
  path unchanged (never wrapped in `ContractError`); an invalid static
  sequence faults at `CliRunner` construction, before any cycle starts.
- **The transcription default — `run_cli` with neither `render=` nor
  `renderer=`** (S3, `docs/RENDERER_CONTRACT_DESIGN.md` §4). The framework renders
  by **transcription**: the fetched data is transcribed (declared-not-invented,
  recursive + wide) through the same `(data, fidelity, width)` contract as any
  authored renderer — "optional renderer" dissolves, there is always a renderer.
  It is a default *renderer*, not a `paint()` call: the compiled `Fidelity` and
  the offered width flow through intact, so `-q`/`-v` and declared budgets visibly
  change the default output. `depth_aliases` and `budgets=True` stay valid on this
  form. The *neither* `@overload` is published (with `fetch` required), so the
  call form is spelled the moment it behaves.

### Changed

- **Render-path declaration validation moves to runner construction**
  (`CliRunner.__post_init__`), not parser construction. The empty-argv fast path
  never builds a parser, and neither `render`/`renderer`/`fetch` mints a flag, so
  a parser-time check would never fire on the bare `tool` invocation. Declaring
  **both** `render=` and `renderer=`, or a missing `fetch=`, each raises
  `DeclarationError` at construction. Declaring **neither** installs the
  transcription default (§4).
- **`tags=` without a renderer faults at construction** (S3, §4). Transcription
  cannot consume `fidelity.visible` — it has no way to map app-domain facet names
  onto arbitrary data — so a declared `Tag` under the default renderer would mint
  a dead `--{name}` flag, the honesty violation `FIDELITY_DESIGN` §1 calls
  structurally impossible. `tags=` with neither `render=` nor `renderer=`
  therefore raises `DeclarationError`, taking the old *neither* fault's place.
- **`transcribe` and `shape_lens` widen to `width: int | None`** (S3, §4) — the
  0.10.1 width law ("absent is natural") reaching the transcription core and the
  exploration entry. `None` propagates through the shared recursive core as
  unconstrained natural sizing; every existing `int` call is byte-identical.
  Inference needs a column budget (chart bars, tree indents are width-consuming),
  so `shape_lens` under a `None` width transcribes the declared shape rather than
  guessing a chart/tree — the guess resumes the moment a width is offered.

**Compatibility** (`docs/RENDERER_CONTRACT_DESIGN.md` §12). `renderer=` and
`ref_schemes=` are additive — no existing `run_cli`/`CliRunner` call needs to
change. `render=` is **documented legacy** as of this release: it keeps
working unchanged, with no runtime warning; a `DeprecationWarning` is deferred
to 0.12, and removal rides the 1.0 freeze window alongside `show()`. Internal
demos and tests were flipped to `renderer=` in the same change that lands
this section (S5) — `raymarch.py` and `starmap.py` deliberately stay on
`render=` until 0.12, as the documented reason the warning gate waits.

A patch cut from the first loops-adoption-spike evidence (roadmap M3): two consumer-recorded workarounds dissolve. Both changes derive from declarations that already existed — the width contract applied uniformly, and section identity read off the declared tree.

### Added

- **Headed sections are addressable** (`docs/DOC_IR_DESIGN.md`, the 0.10.1 anchors amendment). `to_html` stamps `<section id="…">` on every headed section: heading-slug ids (lowercased, non-alphanumeric runs collapsed to hyphens), deduplicated in document order. Unnamed sections declare no identity and get no id. `section_anchors(doc)` joins `painted.publish` (semver-guarded) so a consumer's outline walk reads the SAME map `to_html` stamps from — the loops inquiry article regexed painted's emitted HTML to inject exactly these ids, coupling itself to the serialization's whitespace; that post-pass now deletes.

Consumer-recorded: hit twice in loops' store lens.

## [0.10.0] — 2026-07-11

This release ships **the semantic tree** — the ratified 0.10 amendment to `docs/DOC_IR_DESIGN.md`, earned by trifecta evidence: two worlds (painted's docs site and loops' inquiry article) realize one `Doc` tree as sibling outputs, and the second could reach the publisher only through an `importlib` path hack against a repo checkout. The publisher now ships in the wheel (`painted.publish`), the Inline union settles with `Link` riding the existing ref channel through both projectors, and the node vocabulary graduates through the one-way semver door. Riding along: the render-model laws became executable gates (Milestone 1), `InPlaceRenderer` declares its oversized-frame behavior (RENDER_MODEL §7 Q2b — silent tearing was the one answer the model forbade), and the last `-h` interception asymmetry closes.

### Added

- **`painted.publish` — the doc-IR publisher joins the semver-stable surface.** `to_html(doc, *, fidelity=None)` and `published_fidelity(doc)` move from `tools/doc_publish.py` (which dissolves) into a root module beside `display.py` — the terminal-side entry and the foreign-semantics side, siblings. The category boundary is unchanged (a publisher emits foreign semantics, `<section>`/`<h2>`/`<dl>`, never a `Block`); what moved is the packaging: a second *world* consuming the publisher makes it library surface. Guarded by its own bidirectional snapshot (`STABLE_PUBLISH_SURFACE`).
- **The Inline union settles: `Inline = str | tuple[str | Link, ...]`.** Inside the tuple, plain `str` *is* the text span; `Link(text, target)` is the first rich member, its `target` a ref (`"scheme:value"`) resolved through the declared `RefScheme` — the existing denotation channel, not a new one. One shared walk (`inline_spans`) feeds both projectors, so the two sinks cannot render a span differently: `doc_lens` stamps `ref=target` on the text's cells (the writer's OSC 8 emission and `render_html`'s `<a href>` wrapping already honor it), and `to_html` resolves the same target through the same `resolve_ref` for its chrome anchors. Identical inertness: an undeclared scheme renders `text` as plain content in *both* worlds — painted never invents URIs. Inline positions: `Prose.content`, `Def.summary`/`detail`, `Items.entries`.
- **`Span.ref` — the denotation channel reaches the text primitives.** A `Span` optionally carries a ref, and every `Line` sink honors it the way it honors the span's style: `to_block` stamps it per cell (a wide glyph's placeholder included), `wrap` carries it across line breaks on every fragment (the styled wrap engine's char stream grew a ref lane — one engine, no parallel logic), `truncate` keeps it on the cut span, and `paint` writes it through `put_text`'s new `ref=` parameter (a ref-less write un-links; a write always wins). Ref grids allocate only when a ref is actually present.
- **The doc vocabulary exports.** `Doc`, `Section`, `Prose`, `Def`, `Defs`, `Items`, `Code`, `Figure`, `Link`, and `doc_lens` graduate into `painted.core.__all__` under the semver guard. The disclosure walk (`visible_body`/`capped`) stays unexported — it is the mechanism that guarantees the sinks disclose identically, and painted's two projectors are its only sanctioned readers. `Code(ref=)`'s deprecated alias keeps its 1.0 removal clock.
- **`InPlaceRenderer` declares its oversized-frame behavior: clip with evidence** (`docs/LIVE_DELIVERY_DESIGN.md` §10). A live frame taller than the viewport cannot be repainted — its top rows are already released to scrollback — so on a TTY, `render()` keeps the top rows and a dim `… +N rows` marker (ambient icon set, ASCII degradation) takes the last line. `finalize()`'s deposit writes full height (it belongs to terminal history; nothing repaints after it), and a non-TTY stream has no viewport, so it is never clipped. Previously an oversized frame tore silently — the one behavior the render model forbids outright.
- **The render-model laws are executable gates** (`tests/unit/test_render_model_laws.py`, roadmap Milestone 1). Law 4 (destination independence): identical declarations + argv compile to identical `Fidelity` whatever the terminal, behaviorally and statically. Law 8 (no downstream policy): delivery modules cannot import disclosure policy, with `core/doc.py` the named — and asserted-real — exception. Law 6 (omission evidence): the marked truncation paths are pinned, now including the oversized-frame marker. Law 1 rides in `tests/integration/test_cross_host_content.py`: static and live paths produce equal content Blocks before serialization.

### Changed

- **A tags-only `AppCommand` now intercepts `-h`** — the last asymmetric declaration mirror, one seam over from the 0.9 prompts fix. Any declaration mirror (`help_args`, `add_args`, `prompts`, now `tags`) opts the command into interception; the intercepted help renders the declared Layers group. Behavior change: such a command's handler no longer sees `-h` — the intercepted render (same declarations, same groups) supersedes its `run_cli` help.
- `RENDER_MODEL.md` §7 Q2(b) is stamped resolved (clip with evidence); `DOC_IR_DESIGN.md` build-sequence item 6 flips to done with the pinning evidence named.

### Fixed

- `doc_lens` dropped the ref grid when stamping list markers (`Items` rows), so a link inside a list entry lost its denotation — hit-tests and hyperlinks alike. The marker now lands on the ref-less pad cells and every content cell keeps its ref.

## [0.9.0] — 2026-07-09

This release ships **inline prompts** — the parser's fourth reflection (`docs/PROMPTS_DESIGN.md`). `--force` and `Are you sure? [y/N]` are the same declaration at different fidelities: one resolves from argv, one resolves interactively at a TTY. Declare a prompt beside your tags and `run_cli` generates its flag, its `-h` entry, and completion of its answer values; the answer comes through one door (`ctx.ask`), down one ladder — argv flag → interactive at a TTY → declared default → `ContractError` naming the exact flag that would have answered. Resolution never hangs and never invents an answer: a headless run with no flag and no default gets an honest refusal, not a silent default or a stalled pipe.

### Added

- **`Prompt[T]` and its three domain shapes `Confirm`/`Select`/`Input`**, plus `Danger` and the `MISSING` sentinel (home: `painted.cli.prompts`, re-exported from `painted.cli` — the evolving framework surface). Declarations are promises, validated at construction: a prompt name colliding with a framework flag, a tag, or another prompt raises at parser construction; `danger >= SOFT` forbids `default=` (a ceremony with a pre-filled answer is no ceremony); `HARD` is `Confirm`-only and requires a free-string `challenge=`. `default` is sentinel-guarded, not `None`-guarded: absent means "no declared answer", while `default=None` declares `None` *as* the answer. `Select` takes `values=` or a declared `Vocabulary` (mark styles carry into the rendered choices); `Input` takes `parse=` (`str → T`; its return **is** the answer) and `completer=` (rides shell completion).
- **`ctx.ask(name | declaration)` — the single door.** Memoized by name (a prompt fires at most once; a second ask returns the recorded answer, silently); prompt names are stripped from `ctx.args` (a Tag's answer is in `ctx.args`, a Prompt's answer is behind `ctx.ask`); an undeclared name raises `DeclarationError`. Accepted and named: the fail-late `ContractError` (a mid-run ask can refuse after work has begun) — the guidance is *ask before you act*.
- **The prompt fidelity ladder** — three rungs, resolved per run, never per prompt: **DECLARED** (headless: flag, then default, then refusal — what a script or CI sees), **LINE** (cooked-mode question/answer on stderr — the accessibility floor, and the `--plain` rung), **CELL** (raw-mode in-place components: arrow-key `Select`, single-key y/n `Confirm`, editable `Input`). CELL requires a stderr TTY and cbreak support, probed before any terminal mutation; piped stderr or `--plain` steps down to LINE. Prompt-UI plainness follows the `--plain` *request*, not the resolved stdout format — `--json --plain` still prompts plain.
- **The `(default)` record line.** A default-resolved answer leaves one line of proof on stderr (`✓ scope: local (default)`); flag-supplied answers don't echo — the record line marks an answer the invocation doesn't show. Interactive answers collapse to the same record-line form, so a transcript reads identically however the answer arrived.
- **Danger tiers as ceremony.** `NONE` (y/N, Enter accepts the default) < `SOFT` (an explicit key, no Enter-default) < `HARD` (type the declared challenge to proceed). HARD is fail-closed at every rung: only the exact challenge approves; anything else resolves `False` with no re-prompt. Its flags are a pair — `--name <challenge>` (yes, the exact challenge or a resolution-time `ContractError`; the challenge is never tab-completed) and bare `--no-name` (no) — so a *runtime* HARD confirm is unscriptable by construction (§11).
- **`--no-input`** — one framework flag disabling all interactivity: every prompt resolves as if stdin were not a terminal (flag → default → refusal), verbatim across every mode.
- **Stream discipline (§8): stdout is data, prompts draw on stderr.** Prompt UI, record lines, and refusals all route to stderr; `tool --json | jq` stays parseable even when the tool refused mid-run, and a refusal exits nonzero. `PromptAbort` — a private `KeyboardInterrupt` subclass — marks Ctrl-C inside a prompt so live-stream graceful-stop can never swallow it.
- **The reflections, mirrored.** `run_cli(prompts=)` and `AppCommand(prompts=)` take the same list; declared prompts render a Prompts group in `-h` (intercepted subcommand help included — a prompt-only command intercepts), and completion offers `Select` values and `Input` completions for free.

### Changed

- **`keyboard.py` and `mouse.py` hoisted from `painted.tui` to the package root** — key reading is a delivery-layer primitive with two consumers now (prompts and Surface), not a TUI internal. `painted.tui` re-exports both, so existing imports keep working. `KeyboardInput` hardened in the move: capability probe before any terminal mutation, injectable stream, blocking read.
- **`scrub_control` extracted to `core.cell`** as the single control-character sanitizer (prompt echoes and cell writes neutralize the same way).
- **A one-choice runtime `Select` collapses** — a single-value domain resolves immediately with a `(only choice)` record line instead of rendering a one-item menu.

### Deferred

(All with named triggers in `docs/PROMPTS_DESIGN.md` §11.) Secret/password prompts + the askpass ladder — the one legitimate `/dev/tty` case, deferred by name; multi-select (a domain-shape addition, not a primitive change); timeout-with-default (reintroduces "an answer nobody gave" — wants its own argument); `Select` type-to-filter; the wider `PaintedHandler`/`live_meter` stderr reconciliation stays its own thread.

## [0.8.0] — 2026-07-06

This release ships **`paint()`** — the single display entry point, and the 1.0 keystone: the library's name becomes the verb you call (`docs/PAINT_DESIGN.md`). `paint(subject)` transcribes what a value *declares* — a dict as its key/value pairs, a list as its items, a `dataclass`/`NamedTuple`/`Enum` as its declared fields — recursively, and it never *invents* a shape the subject did not declare. That is the line that made `show()`'s chart-from-a-list guess the sin: rendering a dict *as a dict* is transcription; guessing a chart is interpretation, and interpretation now requires an explicit `lens=`. `show()` becomes a deprecated alias (removed at 1.0), sharing its deprecation horizon with the `id→ref` aliases from 0.7.

### Added

- **`paint(subject, *, zoom=None, lens=None, file=None)`** — the single entry point (home: `painted.display`, re-exported from `painted`). A closed kwarg surface: the meaning channels reachable today (disclosure via `zoom`, arrangement via `lens`) plus the destination (`file`); there is deliberately **no `format`** — JSON is a harness concern (`run_cli --json`). With no lens, `paint()` transcribes the declared shape; a lens is taken only to *interpret* — arrangement that reinterprets the subject as something other than itself (`paint([1,2,3], lens=chart_lens)` claims "these are a series worth plotting"; `paint()` never makes that claim on its own). ANSI vs plain is detected from the resolved `file` (`file.isatty()`), not `sys.stdout`.
- **Transcription is recursive and wide.** A numeric list nested inside a transcribed dict stays items, never a chart — `paint()` never infers at *any* depth. "Declared shape" means stdlib-declared: `dataclass`, `NamedTuple`, `Enum` transcribe as their fields (an `Enum` as `Type.MEMBER`); third-party schema types (pydantic, attrs) are a deferred lane, not reached without a lens.
- **`Writer(no_color=…)` and the `NO_COLOR` contract.** An explicit `no_color=` wins (True or False); otherwise the environment (`NO_COLOR`, honoured when present and non-empty) suppresses foreground/background color while keeping bold/underline/etc. It is orthogonal to `color_depth` — a *forced* depth (as `PaintedHandler` passes on every emit) does not bypass `NO_COLOR`, so piped and CI logs honour it.

### Changed

- **`paint()` is the taught entry, everywhere.** The README hero, the consumer guide's Level 0, the disclosure ladder's rung 0, the demo curriculum (`demos/primitives/paint.py`), and the "no cliffs" walkthrough now lead with `paint()` and the altitude story — the same verb every layer up the stack renders through. The walkthrough's stage 01 leads with genuine transcription output and reveals severity bars as the opt-in *lens* claim, not something `paint()` invents.
- **`shape_lens` (semver-stable, `painted.views`) now renders a non-numeric tuple as an item list**, matching `list` — container dispatch now matches `(list, tuple)` rather than `list` alone. Previously a non-numeric tuple fell through to the `str()` fallback (`"(1, 'x')"`); nested non-numeric tuples drift the same way. Numeric tuples are unaffected — they still dispatch to `chart_lens` on the inferring path.

### Fixed

- **A zero/composite `Flag` value no longer renders as `'TypeName.None'`.** A `Flag`/`IntFlag` with no single named member (`.name is None` — a zero value or an OR'd composite) now falls back to the enum's own `str()` (`'Perm(0)'`, `'Perm.R|W'`) instead of the misleading `f'{type}.{None}'` string. Reachable via both `paint()`'s Enum scalar-exclusion and `lens=shape_lens`.
- **The `set` branch now includes `frozenset`.** Previously a `frozenset` fell through to the `str()` fallback; it now renders as tags, matching `set`.

### Deprecated

- **`show()` — deprecated retained alias, removed at 1.0.** It keeps its pre-0.8 render body (the `shape_lens`-*inferring* default) and warns on every call, but **narrows**: `format=` is accepted and ignored (JSON/plain are a harness concern, `run_cli`). Two behavioural drifts are accepted rather than fenced off behind a `paint()`-only branch, both because `show()` shares `paint()`'s render core: (1) a top-level `IntEnum`/`StrEnum` — which previously hit the scalar short-circuit and rendered `str(value)` (`'ok'`, `'1'`) — now reaches the renderer and prints `Type.MEMBER` (`'Status.OK'`); a bare `Enum` already rendered `Type.MEMBER` on 0.7 and is unaffected, as are nested `Enum`s. (2) container dispatch now matches `(list, tuple)` rather than `list` alone (see Changed), so `show((1, 'x'))` drifts from the `str()` fallback to a dash-item list, and nested tuples drift the same way. `show()` is removed at 1.0, so propping up a dying alias's exact bytes for either drift is not worth the seam.

### Deferred

- **`paint(exc)` renders `str(exc)`, not `render_traceback`** (the framework-worn path — `install()` / `PaintedHandler` — already renders tracebacks, so direct `paint(exc)` waits on demand). **Container dispatch keys on the concrete `dict`/`list`/`tuple`**; an abstract `Mapping` (e.g. `MappingProxyType`) or `Sequence` (e.g. `range`) renders via `str` (`str`/`bytes` *are* `Sequence`s — the ABC net is leaky). Both are design-intent in `docs/PAINT_DESIGN.md` §3, deferred pending demand.

## [0.7.0] — 2026-07-05

This release ships **ref deliveries** — the denotation channel reaches every delivery that can express it (`docs/REFS_DESIGN.md`). The per-cell annotation has existed since 0.1.2 (`Block.text(id=)`, threaded through every compose op, read by TUI hit-testing); it now takes its ratified name — **ref** — and gains its two missing readers: OSC 8 hyperlinks in ANSI output and `<a href>` anchors in HTML. Resolution is a declaration: a `RefScheme` turns `scheme:value` refs into URIs, and without one, refs stay inert in every delivery — painted never invents URIs. Scheme-less refs (`ref="sidebar"`, the hit-testing idiom) stay inert in link deliveries by design.

### Added

- **`RefScheme`, `use_refs`, `current_ref_schemes`, `reset_refs`, `resolve_ref`** — the denotation channel's declaration, sibling to `Vocabulary` on the semver-stable views surface (home: `painted.refs`, re-exported from `painted.views` and `painted`). `RefScheme(name, resolve)` validates at construction (kebab-case name, callable resolver → `DeclarationError`); `use_refs(*schemes)` is the usual dual setter/context-manager with REPLACE semantics; `resolve_ref(ref)` is the single choke point every link delivery reads — inert (`None`) on scheme-less refs and undeclared schemes, and a resolver's own exceptions propagate unwrapped (a resolver fault is the app's, not painted's). Ref schemes generate no CLI flags, enforced structurally.
- **OSC 8 hyperlinks in ANSI deliveries.** Both emission loops — `Writer.write_ops` (Surface/TUI diff path) and `render_row_ansi` (`print_block`/`InPlaceRenderer` path) — hold a `last_ref` state machine parallel to `last_style`: adjacent same-ref cells share one link, a ref-only change re-anchors even when style is unchanged, and an open link always closes at row end, on scroll, on a cursor jump, and before the final reset. Emission requires all three gates: a declared scheme that resolves the ref, ANSI format, and `Writer(hyperlinks=True)` (the explicit opt-out — OSC 8 is progressive enhancement, so there is no detection). Resolver output is tolerated as data: URIs are percent-encoded so a control byte can't inject a second escape sequence, and an empty-string URI is inert (an empty OSC 8 target *is* the close sequence).
- **`<a href>` anchors in `render_html`.** Same ambient resolution, no signature change — the docs-site pipeline picks refs up without threading a parameter. Anchors wrap style spans and never interleave with them; transitions key on the ref (two refs resolving to one URI still re-anchor); hrefs are attribute-escaped, and an empty-string URI is inert here exactly as in ANSI (`<a href="">` is a self-link, not a denotation). The `refs_anchors` panel pins the delivery in the docs site, and `demos/primitives/refs.py` is the runnable specimen.
- **`CellWrite.ref`** — the change stream carries denotation. `Buffer.diff` compares ref slots whenever either buffer has a ref grid, closing the stale-hyperlink blind spot (same glyph, same style, different ref now redraws); the scroll-optimized Surface flush and `InPlaceRenderer`'s row comparison honor refs the same way. The no-refs fast path is unchanged.
- **Refs across the demo curriculum** — one demo per tier, matching the feature's altitude. `demos/primitives/refs.py` (the type: a ref becomes a link through a declaration, inert without one); `demos/patterns/denotation.py` (the workflow: a `record_line` feed whose payload lens stamps refs on summaries — the first `record_line` demo — read two ways, `resolve_ref` at `-v` and `Buffer.hit` probes at `-vv`); `demos/showcase/starmap.py` (the spectacle: a real 64-star catalog with constellation figures, spectral truecolor, deterministic twinkle, and a drifting-RA `--live` pan — every star an OSC 8 link to its Wikipedia article).

### Changed

- **The per-cell channel's word is `ref`, everywhere.** `Block.text/column/empty(ref=)`, `Block(ref=, refs=)`, `Block.ref`, `Block.cell_ref`, `border(ref=)`, `Buffer.put_ref`/`BufferView.put_ref`; `Surface.hit` keeps its name and returns the ref. `Focus.id` is untouched — a different concept in a different subsystem; the law is one word for the per-cell channel, not a ban on `id`.
- **`Code.ref` → `Code.src`** (doc-IR). The field is an authoring-time content locator, not a render-time denotation; with `ref` becoming the channel's word, the collision is cleared in the same change.

### Deprecated

- **Every old spelling keeps working behind a `DeprecationWarning` until 1.0**: `id=`/`ids=` kwargs, `Block.id`, `Block.cell_id`, `border(id=)`, `put_id`, `Code(ref=)`. Passing both the new and the deprecated spelling in one call raises `ContractError` rather than silently preferring either. Pickles written by ≤0.6 carry the pre-rename slot names and still load (`__setstate__` remaps them through the same deprecation window). Alias removal lands at 1.0 alongside the `show()` alias removal — one deprecation horizon.

## [0.6.0] — 2026-07-05

This release adds **declared vocabularies** — the mark channel's mechanism, and the rule that every color a renderer applies for *meaning* traces to a declaration (`docs/VOCABULARIES_DESIGN.md`). A vocabulary is a closed set of named values bound to roles, validated at construction; `mark_style(vocab, value)` is the single point meaning becomes color. Severity is reframed as the *built-in* ordered vocabulary (the depth-vs-Tag pattern repeating: painted ships the anonymous axis, apps extend it), and painted takes its own medicine — the three hardcoded `record.py` gutter if-chains are now ordered vocabulary declarations over one `record_gutter` factory.

### Added (vocabularies)

- **`Vocabulary`, `Role`, `Thresholds`, `use_vocabularies`, `mark_style`, `current_vocabularies`, `reset_vocabularies`** — the declaration mechanism, on the semver-stable views surface. Construction validates everything (the `check_declarations` discipline): unique bound values, resolvable role references, no conflicting role redeclarations. Ordered vocabularies unlock `index`/`at_least`/`cmp` and `Thresholds` (numeric floors → values, greatest-floor-cleared). The honesty rules are pinned by tests: an undeclared lookup raises; an out-of-vocabulary value raises unless `overflow="series"`; vocabularies generate no CLI flags (enforced structurally).
- **`Palette.series_for(key)`** — deterministic categorical color for open sets: md5 of the key into the `series` ramp, never builtin `hash()` (PYTHONHASHSEED). The digest is golden-pinned; `flame_lens` rebased onto it, shedding its per-process color instability. An empty `series` ramp degrades to a bare `Style()` (unstyled, never an `IndexError`) in both `series_for` and `flame_lens`.
- **`Theme(roles={...})`** — the public path to re-tinting any declared role by name (core or app); a fourth composed ambient channel that `use_theme`/`reset_theme` set and restore atomically. The roles mapping makes `Theme` un-hashable by reviewed decision (value-equality holds; nothing hashed a Theme).
- **`record_gutter(vocabulary, field, *, aliases=, thresholds=, glyphs=, unknown=, default=)`** — gutters consume vocabularies instead of owning them. On the `thresholds` path, a payload missing the field resolves `default=` (0 unless declared) through the same floors — absent data is classified, not special-cased. Glyph weight derives from a value's distance to the vocabulary's `attention` end against a ramp; color resolves through the same seam as `mark_style`, so a palette swap re-tints rails live. The three shipped gutters are now declarations over it, byte-identical for every known status; a rail never raises on data — out-of-vocabulary or wrong-type payload values route to the declared `unknown` fallback.

### Changed (vocabularies)

- **Severity's two internal role maps collapsed into one built-in declaration.** `Severity` (the enum) is unchanged as its typed spelling; `callout` and `PaintedHandler` both resolve through the built-in `severity` vocabulary (so both now honor `Theme(roles=)` overrides — the handler snapshots resolved styles at construction, its documented discipline). `DEFAULT_THRESHOLDS` is re-expressed through `Thresholds`: a record below every declared floor now resolves to the smallest floor's value rather than a hardcoded INFO — identical under `DEFAULT_THRESHOLDS`; an empty `thresholds=` now raises at construction.

---

It also adds **diagnostics** — painted renders the two surfaces every program already emits, log records and uncaught tracebacks, as structured Blocks disclosed by zoom rather than format strings. A log level is a *declared severity* (levelno thresholds collapse onto the closed `Severity` vocabulary); a traceback is a *record tree* (frames are records on a gutter rail, cause/context chains and groups are the tree), and capturing the exception is the declaration. The delivery glue lives at the package root, not `painted.cli` — a log handler and an excepthook aren't argv-driven, and the CLI layer holds a frozen tripwire (nothing in `cli/` imports the renderer). The one new semver-stable name is `render_traceback` (`painted.views`); `PaintedHandler`/`install`/`DEFAULT_THRESHOLDS` are on the evolving root surface.

### Added

- **`render_traceback` — an exception as a record tree.** `render_traceback(exc, zoom, width, *, suppress=(), redact=default_redact)` renders a live `BaseException` (captured internally, `capture_locals` only at FULL) or a pre-captured `TracebackException` (the serializable / Fact-friendly boundary) as a Block. Frames are records on a continuous gutter rail encoding one dimension — frame origin (app vs suppressed/library); cause/context chains and `ExceptionGroup`s are the tree. The zoom ladder is additive: MINIMAL (type + message + innermost frame, one line) → SUMMARY (frame stack, chains summarized, suppressed frames folded) → DETAILED (source ±1 with a display-column-correct caret, chains fully rendered) → FULL (source ±3, redacted + budgeted locals, groups expanded). `suppress` folds frames whose module path matches a substring to one muted line (declared and output-changing); `default_redact` masks local names matching `password|secret|token|key|api` at FULL. Exported from `painted.views`.
- **`PaintedHandler`, `install`, `DEFAULT_THRESHOLDS` — diagnostics delivery.** `PaintedHandler` is a `logging.Handler` that *renders* each record (timestamp + severity-styled level + logger + message + `extra` payload + any `exc_info` traceback) to a Block and writes it atomically under the handler lock — a renderer, not a formatter (`setFormatter` shapes the message string only; the structure stays painted's). The palette and color depth are snapshotted at construction, so worker-thread logs render with the aesthetic the main thread declared. `DEFAULT_THRESHOLDS` maps `levelno` floors onto `Severity` (DEBUG→INFO muted, CRITICAL→ERROR); a custom mapping changes output. `install()` routes `sys.excepthook` through `render_traceback` (byte-identical to the explicit `print_block(render_traceback(...))` path); `threads=True` opts into `threading.excepthook`, and `KeyboardInterrupt` passes through untouched. Exported from the root `painted` facade.
- **`PaintedError`, `DeclarationError`, `ContractError`, `LifecycleError` — a named fault taxonomy.** painted has raised bare `ValueError`/`RuntimeError` since its first commit; these four classes name *when* a fault fires and *what the fix is*, replacing message-regex discrimination with a type a consumer can `except`. `PaintedError` is the root (never raised directly — catch it to mean "any painted fault"); `DeclarationError(PaintedError, ValueError)` is a malformed declaration caught at construction/registration time (fix your code); `ContractError(PaintedError, ValueError)` is a bad value at a render-path call site (usually fix your code, but an app feeding semi-trusted data may catch and fall back); `LifecycleError(PaintedError, RuntimeError)` is the right call in the wrong state (fix the call sequence). Each subclass dual-inherits the stdlib type it replaces — the same pattern as `json.JSONDecodeError(ValueError)` — so every existing `except ValueError`/`except RuntimeError`, ours and consumers', keeps working unchanged; this is additive and semver-MINOR, not a break. Home is `painted.core.errors`, re-exported from `painted.core` and `painted`. See `docs/ERRORS_DESIGN.md` for the full hierarchy, the classification rule, and the site-by-site taxonomy of every raise in the library — including the vocabulary, gutter, and logging-handler declaration sites, which validate through the same taxonomy. An architecture invariant rejects any new bare `ValueError`/`RuntimeError` raise in the library.

### Fixed

- **`shape_lens` no longer crashes on cyclic or deeply-nested containers.** A self-referential container raised `RecursionError` in `show()`/`shape_lens`; the lens now threads a `seen`-id set through the recursion and emits a muted `↻ <cycle>` marker on revisit, and caps absolute depth (default 6) with a muted `…`. It also grows a declared-schema branch checked before the generic `str()` fallback: a `@dataclass` renders its `fields()` (honoring `repr=False` as declared suppression), a `NamedTuple` its `_asdict()`, an `Enum` its `TypeName.MEMBER` — every field value routed back through the budgeted, cycle-safe path. attrs/pydantic detection is deferred (see `docs/DIAGNOSTICS_DESIGN.md`).

## [0.5.1] — 2026-07-01

A patch release fixing four defects in 0.5.0's shell completion, found in a post-release review and its field verification. All fixes are in the completion machinery (`painted.cli`); no API surface changes. **If you installed completion from 0.5.0, regenerate the glue** (`<prog> completion zsh --install`, or re-run your `> _<prog>` redirect) — two of the fixes live in the generated script.

### Fixed

- **zsh candidates no longer duplicate.** The generated zsh function ended with `(( files )) && _files`, which returns exit status 1 whenever no file directive was sent; compsys reads a nonzero return as "found nothing" and retries the function once per `matcher-list` entry, re-adding every candidate each round — with the common three-entry matcher-list (case-insensitive + partial-word), every candidate appeared three times. The function now returns an explicit status.
- **zsh completion works on compound command lines.** The generated zsh function passed `$BUFFER`/`$CURSOR` — the *entire* edit buffer — so on a compound line (`git pull && <prog> dem<TAB>`) the transport stripped the wrong program word and completed nothing. The function now reconstructs the buffer from `${words[1,$CURRENT]}`, zsh's completion array already scoped to the current command. bash was unaffected (readline provides per-command `COMP_LINE`/`COMP_POINT`).
- **One shared token walk in the producer.** `_count_consumed_positionals` and `_present_option_strings` walked the preceding tokens with independent, subtly different models (inline short values like `-n5` were classified differently), so positional tracking and mutex suppression could disagree about the same line. Both are now reductions over a single shared walk (`_walk_preceding`) and cannot diverge. Multi-token positionals (`nargs=2+`) remain unmodelled — a pre-existing, documented completeness gap, not a regression.
- **One tolerant line splitter.** `complete_line` used a weaker duplicate of the transport's quote-tolerant splitter (naive whitespace fallback without closing a dangling quote); the tolerant version is now the single implementation, shared by both paths.

## [0.5.0] — 2026-07-01

A minor release adding **native shell completion** — the parser's third reflection. A painted CLI already reads its argparse parser two ways (parse → run the command, and `-h` → render help); 0.5.0 adds the third (TAB → candidates) from the *same* single walk, so the flag you see under `-h` is exactly the flag that completes. Completion is native and zero-dependency (no `argcomplete`/`shtab` at runtime) and *dynamic* (a `.completer` callback answers TAB from live data, not a frozen generated script), and its **machinery is render-free by construction** — pressing TAB imports none of the rendering core, so completion is instant no matter how expensive the program is to run, and typing TAB never triggers the work the command would do. `run_app` auto-injects a `completion` command into every roster; zsh and bash ship. All additions are additive and confined to the evolving `painted.cli` surface — the semver-stable `painted.core`/`painted.views` are untouched (no name added or removed).

### Added

- **Native, dynamic shell completion + the `completion` command.** Every `run_app` now carries an auto-injected `completion [shell] [--install] [--dry-run]` command (skipped when the app already owns one): `completion zsh` / `completion bash` print the shell glue, `--install` writes it to the shell's standard user-completions directory — a file painted *owns*, never a dotfile it edits — and prints the one remaining manual step, and a bare `completion` auto-detects the shell from `$SHELL`. TAB then completes subcommand names, declared flags, choice values, and open-slot file paths (classified by painted, walked by the shell so `~`-expansion and the user's own `zstyle` keep working). Completion is *honest* — it under-lists rather than offer a flag the parser would reject (a mutually-exclusive sibling already on the line is suppressed; a candidate is never invented).
- **The `.completer` dynamic seam + `complete_via`.** Attach a completer callable to any argparse action to answer TAB from live data: `complete_via(parser.add_argument("target", ...), my_completer)` returns the action, so attachment is one inline line (the typed front door, symmetric with the `action.completer` attribute argcomplete reads — the raw attribute still works). The completer receives a `CompletionContext(args, prefix)` — `args` is the parsed args resolved so far (an `ArgsView` over the tolerantly-parsed namespace), `prefix` the partial token under the cursor — so it can scope its candidates to what the user has already typed and prefix-parse a structured token. It returns `Candidate`s (a value plus an optional description → zsh's described rows) or bare strings. This is the seam behind painted's own render-free `demos` name completion — and its `docs` completer, which deliberately loads the renderer as the honest contrast — and the vehicle for domain-value completion (completing a data source's live keys at TAB). The render-free guarantee covers the machinery; a completer you attach may load whatever it reflects.
- **`AppCommand.add_args` — one declaration serves parse, `-h`, and completion.** Pass a parser-builder callback to both `AppCommand(add_args=…)` and the handler's `run_cli(add_args=…)`, and a single declaration feeds all three reflections of the parser. It supersedes `help_args`, which only *re-describes* args for `-h` and cannot feed completion (its description strings never become real parser actions); `help_args` remains for description-only use.
- **Completion producer surface.** New public contract types and engine on `painted.cli` for consumers driving completion directly: `Candidate`, `CompletionContext`, `Completer`, `complete_via`, plus the producers `complete_args` (one command), `complete_app` (an app roster, forwarding to the matched subcommand), and `complete_line` (a raw edit buffer).
- **`build_parser` / `ArgsView` — render-free parser introspection.** `build_parser` constructs a command's argparse parser without the renderer or a `fetch` callback, and `ArgsView` is the render-free view of parsed args exposed as `ctx.args`; both are exported so completion — and any consumer — can walk a parser's arguments without dragging `core.block` / `core.doc` onto the no-renderer-on-TAB path.

## [0.4.0] — 2026-06-22

A minor release adding a batch of consumer-driven primitives and widening one contract, each landed where a downstream consumer (the loops rebuild, and the siftd terminal-UI refresh) reached a real call-site. `record_line`/`record_line_composed` now accept `width=None` for natural sizing; `table()` gains a controlled-shrink overflow mode and per-column ellipsis markers; a new `callout` primitive renders severity-tagged messages; the `Palette` can now own body text (and an optional canvas); the truncation marker degrades to ASCII via a new `IconSet` slot; a `rule()` divider plus rank-tier glyphs round out the gutter vocabulary; multi-style `Line`s gain a `wrap()` reflow rung to match single-style `Block.text`; and the wcwidth-aware `display_width` measurement graduates from a private module to the stable `painted.core` surface. Backward-compatible for well-formed input — `width=int` and existing callers render unchanged; the one behavior change is that C0/C1 control characters in text are now neutralized to spaces instead of emitted verbatim (see Changed).

### Added

- **`display_width` graduated to the stable surface.** The wcwidth-aware display-column measurement (`display_width(text) -> int`) is now exported from `painted.core` (semver-stable), promoted from the private `painted.core._text_width`. It is painted's foundational width primitive — "a block's display width is not `len()`" — and a consumer laying out its own content had no public way to measure columns; the siftd terminal-UI refresh reached into the private module from four call-sites. The function is unchanged (falls back to `len()` for non-printable strings); only its home becomes public. `core`-only on purpose — measurement is a primitive and `core` is its honest home, not a second `views` re-export to owe forever.
- **`Line.wrap()` — multi-style reflow.** New `Line.wrap(width, *, wrap=Wrap.WORD) -> Block` reflows a multi-style `Line` across rows, the multi-line generalization of `Line.to_block` (which is single-line `Wrap.NONE`). It restores the rung the disclosure ladder was missing for styled text: `str` already had `Block.text(..., wrap=…)`, but `Line` — the mixed-style primitive — only had single-line `truncate`/`to_block`, so the moment text carried a second style, reflow vanished and the caller fell to hand-laying cells. `wrap` mirrors `Block.text`'s four `Wrap` modes exactly; each span's style merges onto the `Line` style and rides with its characters across line breaks; pad cells and the ELLIPSIS marker inherit the `Line`'s base style. Under the hood the wrap engine is now unified — `_char_wrap`/`_word_wrap` operate on a styled-char stream and the `str` path is the uniform-style adapter over it, so single-style output is byte-identical to before (source spaces preserved, break space right-trimmed).
- **`Palette.text`/`surface` — substrate ownership.** A `Palette` can now own "body text" (and optionally a base canvas), not just the five semantic roles. The new optional `Palette.text`/`surface` Styles supply a default `fg`/`bg` wherever a cell's `Style` leaves `fg`/`bg` unset; an explicit `fg`/`bg` on the cell always wins. Both default to `None` — byte-identical to today's terminal-default behavior. Resolution is a single pure pass (`Palette.resolve_style`, layering `text` under the cell style and `surface` as the base `bg`) applied at the writer's two SGR-emission sites; the `Style → SGR` conversion stays pure. Previously a theme could color only the five roles, so it could not make plain text theme-wide.
- **`rule()` divider primitive.** New public `rule(width, *, char=None, style=None) -> Block` on `painted.core.compose` renders a horizontal divider: one row of `char` exactly `width` columns wide, honoring the width contract. `char=None` reads the ambient `IconSet.rule` (new slot, `─` / ASCII `-`) so it degrades like every other glyph; `style=None` reads `current_palette().muted`. Exported from `painted` and `painted.core` (semver-stable). Replaces the hand-drawn `char * n` + ASCII-fallback idiom consumers were repeating.
- **`IconSet.ellipsis` slot — ASCII-degradable truncation marker.** The truncation marker is now a glyph slot (`…` / `ASCII_ICONS` `...`) rather than a hardcoded literal. Every marker site routes through the ambient icon: `compose.truncate` and `_text_width.truncate_ellipsis` default `ellipsis=None` → `current_icons().ellipsis`; `block.py`'s `Wrap.ELLIPSIS` reads the ambient marker and reserves its full display width (no longer assuming a one-column ellipsis, so a multi-column `...` correctly cuts content to make room); the table per-column ellipsis path inherits it. Under `use_icons(ASCII_ICONS)` truncation degrades to `...` everywhere, and a strict-ASCII stream no longer raises `UnicodeEncodeError` mid-render on the `…` codepoint. Defaults preserve Unicode behavior exactly.
- **`IconSet` rank-tier glyphs.** A rank ladder for attention/relevance rails — `rank_top` `◆` / `rank_mid` `│` / `rank_tail` `·` (ASCII `*` / `|` / `.`). `views`' `apply_attention` now reads its high-rank marker and collapsed-line dot from the ambient `IconSet` instead of hardcoding `◆`/`·`, so they degrade with every other glyph.
- **`table()` `Overflow.FIT` mode + per-column ellipsis.** `Overflow.FIT` is a controlled-shrink policy (the `resolve_column_widths` follow-up): `Fill` columns size to content and never stretch into slack; when over budget they shrink toward their `min_width` floors to absorb the overflow; and if the non-`Fill` columns alone exceed the budget the table overflows at natural width rather than clipping — so no column or value is ever silently dropped. `Overflow.CLIP` (default) keeps the historical right-clip. `Column.ellipsis=True` adds a `…` marker on truncation, with `ellipsis_side` choosing which end survives: `EllipsisSide.END` keeps the head (`"long descrip…"`), `EllipsisSide.START` keeps the tail (`"…Code/siftd"`, so a path leaf survives), backed by a right-anchored `_truncate_keep_end`. `ellipsis=False` keeps the historical marker-less cut. `Overflow` and `EllipsisSide` (a dedicated two-valued type, not a reuse of `Align`) are exported from `painted.views`.
- **`callout` message primitive.** `painted.views.callout(subject, *, severity, detail, hint, box, width) -> Block` renders a severity-tagged message line: `severity` (a new `Severity` enum — `SUCCESS`/`INFO`/`WARNING`/`ERROR`, not a free string) drives both the glyph (ambient `IconSet`) and the color (ambient `Palette` role), with an optional muted `detail` line, an optional muted `↳ hint` next-step line, and an optional bordered panel. `width` is exact (the painted width contract): content is clipped or padded to it, and with `box=True` the border counts toward the budget (the inner content fits to `width - 4`) so a boxed callout never exceeds its width; `subject`/`detail`/`hint` render as clean single rows — control characters are neutralized library-wide (see Changed), so no input can split or corrupt the block. Fills the message/callout gap alongside `table`/`record_line`/`progress`. `callout` and `Severity` are exported from `painted.views`.
- **`IconSet` severity ladder.** A coherent 4-level severity ladder (`ok ✓` / `info ℹ` / `warn ⚠` / `error ✗`) plus a `↳` hint arrow, each with aligned single-char ASCII (`+` / `i` / `!` / `x` / `->`) so callouts degrade canonically under `use_icons(ASCII_ICONS)`. Distinct from the generic `check`/`cross` pass-fail markers.

### Changed

- **Control characters neutralized at the cell level.** `Cell` — and therefore every text primitive built on it (`Block.text`, `record_line`, `table`, `callout`, …) — now replaces C0/C1 control characters (`U+0000`–`U+001F`, `U+007F`–`U+009F`: tab, newline, carriage return, raw ANSI/`ESC`, etc.) with a space at construction. Previously they were emitted verbatim, so a tab silently broke the width contract at the terminal and a raw `ESC` could issue cursor/erase sequences out from under the renderer (notably corrupting a `Surface` diff). Replacement keeps display width stable — each control char was already measured as one column (`char_width`) — and matches `render_big`'s existing `\t\n\r`→space handling. The C0/C1 ranges are exactly Unicode category `Cc`, tested by ordinal: zero-width joiners (emoji sequences, `Cf`), private-use glyphs (icon fonts, `Co`), box-drawing, and combining marks are category-distinct and pass through untouched. Output for control-char-free text is unchanged.
- **`record_line`/`record_line_composed` accept `width=None` (natural sizing).** Previously `width` was a mandatory `int` and `record_line(width=None)` raised `TypeError` (it computed `width - meta_width`). `None` now selects natural sizing — no padding, no truncation, the record keeps its intrinsic width — exactly the omit-width escape that `Block.text(text, style)` already documents. `record_line` was the outlier that didn't honor it. At every zoom, content (default summary, `PayloadLens` strings/Blocks, secondary fields, FULL field lines) renders untruncated; `record_line_composed` propagates `None` to the inner line and still applies gutter (height-based) and attention markers. `apply_attention`'s `width` is correspondingly `int | None`. No public-API names added or removed; `width=int` callers render identically.

- **Depth aliases for app-local zoom spellings.** `run_cli(depth_aliases={"brief": 0, "full": 3})` adds app-named spellings of the depth axis. Each alias generates a `--{name}` flag in the same mutually-exclusive group as `-q`/`-v` and sets depth directly. It is pure spelling: an alias to depth 0 implies `--static` exactly like `-q` because the runner checks the compiled `fidelity.depth`, not the flag, and the alias inherits any facet implications at its resolved depth.
- **`build_fidelity` escape hatch.** `run_cli(build_fidelity=fn)` runs a `(namespace, Fidelity) -> Fidelity` hook *after* tag, alias, and budget compilation, so the hook sees the fully compiled spec. It is the residue seam for disclosure logic the declarative grammar cannot express — for example, reading an env var as a baseline depth.
- **Declaration collision and validity checks at parser construction.** Declared tag and alias names are validated when the parser is built, not at runtime: a name must be lowercase kebab-case, must not collide with a framework flag (`--quiet`, `--json`, `--max-chars`, …), and must not collide with another declaration (tag↔tag, tag↔alias); a negative alias depth also raises. Framework names are reserved regardless of `modes=`/`budgets=` filtering, and a custom `add_args` arg can no longer silently land on a declared dest — it raises a construction-time `ValueError`.
- **`Fidelity.implied_visible` and `help_doc` are public on `painted.cli`.** Two new names join the evolving `painted.cli` surface: `implied_visible(tags, depth)` (the shared depth→facet implication law, so non-CLI harnesses resolve a depth into the same visible set the flag compiler produces) and `help_doc(runner)` (the doc-IR `Doc` the help screen is now built from).
- **`painted docs` command.** A terminal front door that renders authored documentation pages as live output: `painted docs` lists pages, `painted docs <name>` renders one. Pages dispatch through `run_cli`, so `-v`/`-vv` thread to `Fidelity.depth` and tagged layers surface as declared flags — `--rationale` appears exactly on pages that have rationale-tagged nodes. Ships one page (primitives), authored as a node tree with a live `Figure` specimen (doc == demo).
- **Two-tier live delivery via `run_cli(live_delivery=)`.** `run_cli` now selects between two live tiers with `live_delivery="inplace"|"surface"` (default `"inplace"`, back-compatible). The `"surface"` tier hosts `fetch_stream` on an alt-screen `StreamSurface` that diffs absolute per-cell — structurally immune to the scroll-tearing relative cursor addressing suffers — then deposits the final frame to the normal screen on exit; the in-place tier stays ephemeral liveness in scrollback. An invalid value raises at construction. With `"surface"`, `-i` and `--live` converge onto the same surface.
- **Opt-in delivery-cost gauge via `run_cli(live_meter=)`.** `run_cli(live_meter=True)` lets the framework gauge its own live delivery: both live tiers measure render+write cost per frame and dress each delivered frame with a `cost_meter` row. The budget is measured, not declared — the median inter-frame period — so the gauge self-calibrates to any cadence. Opt-in (default `False`) so existing `fetch_stream` apps' output never changes unbidden; opted-out runs pay nothing, and pipes/static output are never dressed.
- **`cost_meter` views component.** `cost_meter(samples_ms, width, *, budget_ms, label, palette)` joins the public `painted.views` surface: a single-row gauge that renders observed per-frame costs against a time budget, returning `None` when nothing was observed so static output stays undressed. The role encodes headroom — success under 50% of budget, warning under 90%, error at or beyond — and the fixed-format cost plus padded sparkline hold row width stable so bordered windows never breathe.
- **`AppCommand.aliases` for multi-command apps.** `AppCommand` now takes an `aliases` tuple; dispatch routes on the command name or any of its aliases, and aliases surface in top-level help as a parenthesized suffix on the command row (e.g. "demos (alias: demo)", pluralized for multiple). Names and aliases share one dispatch namespace.
- **Construction-time validation of command names and aliases.** `AppRunner` now rejects ambiguous routing at construction: a command name declared by more than one command, an alias equal to its own command's name, the same alias listed twice on one command, an alias colliding with a command name, or an alias colliding with another command's alias all raise `ValueError`. Misconfiguration is caught at wiring time rather than silently shadowing at dispatch.
- **`fit_to_width` block primitive.** New public `fit_to_width(block, width)` realizes the width contract at the block level: truncate (with ellipsis) if wider, pad with spaces if narrower, identity if exact. Horizontal-only — it clips rather than reflows, so wrap content first to grow height instead.
- **`PAINTED_PALETTE` and `PAINTED_THEME` presets.** A vivid, truecolor-first palette and its matching theme ship as named presets alongside `DEFAULT`, `NORD`, and `MONO`. The name is the semver contract; the hex values are tunable. Both are exported from `painted` and `painted.views`.
- **`Palette.series` categorical ramp.** `Palette` gains a `series` field: a categorical (qualitative) ramp of Styles indexed by position, distinct from the five semantic roles, for visually separating N peers. `flame_lens` now consumes `current_palette().series`. Each preset defines its own ramp (`MONO` uses modifier-only styles, no hue); a custom `Palette` with no series gets the default red/yellow/green/cyan ramp.
- **Architecture guard `test_public_names_do_not_shadow_submodules`.** A static guard that prevents a public name equal to a submodule filename from being permanently shadowed by the module object once anything imports the submodule.
- **Internal: doc-IR document compositor (provisional, not yet public).** Adds the doc-IR — a fixed document node vocabulary (`Doc` root over a `Node` union of `Section`/`Prose`/`Defs`/`Items`/`Code`/`Figure`, with `Def` as a `Defs` entry) and `doc_lens`, the projector that lays a document out into a `Block`. Disclosure is governed by `Fidelity` via a per-node effective tier (`eff = depth - min_depth`, plus a tag check) that cascades through Sections, so list density expands without re-authoring content. Lives in `core/doc.py` as a peer of `compose.py` (moved there from `views/lens`) so it imports only `core`, but is deliberately held out of `painted.core.__all__` until the Inline-union and `Code(ref)` authoring seams settle.
- **Internal: dev/docs infrastructure.** The Astro docs site is folded into the monorepo at `web/` so one generator regenerates the in-repo docs and the external site's panels together and they cannot silently drift; `tools/outputgen.py` renders real painted Blocks to HTML/plain/JSON panels with a `./dev check` "Outputgen" tier gating committed output against a fresh render; `tools/doc_publish.py` adds `to_html`, a *tools-only* publisher that emits semantic HTML (`<section>`/`<h2>`/`<dl>`) from the same doc node tree the terminal lens renders, sharing the one `visible_body`/`capped` disclosure walk so terminal and web cannot disclose differently. Backed by a docgen fragment/region engine (`./dev docs`), reference/landing specimen catalogs of real Block renders, the animated demo curriculum (rungs 1–6: plasma, fire, boids, lorenz, wireworld, raymarch), the full-ladder disclosure exemplar in `demos/patterns/fidelity.py`, and the stdlib-only `tools/term_probe.py` DEC 2026 diagnostic. `web/`, `tools/`, `demos/`, and `docs/` are dev infrastructure only — the wheel ships `src/painted` and stays zero-dependency.

### Changed

- **Width is an exact contract.** A passed `width` is now exact everywhere blocks are produced — blocks, lenses, records, and composers all satisfy `block.width == width`: short content is padded, too-wide content is clipped, never overflowing horizontally. Pass `wrap=Wrap.CHAR`/`Wrap.WORD` to reflow into more rows instead of clipping; omit `width` for natural content sizing. Exactness lets callers carve a width budget into pieces that tile with no gap or overflow at any terminal size.
- **`Fidelity` is the canonical compiled disclosure spec.** `Fidelity` is the single compiled disclosure spec — `depth` (anonymous detail), `visible` (named facets resolved at compile time), `chars`/`lines` (density budgets) — travelling whole through `CliContext.fidelity`. Renderers beyond rung 1 receive the spec intact rather than exploded into kwargs; `ctx.zoom` is the rung-1 porthole. Docstrings reframe the prior "three-axis" story as the honest disclosure ladder.
- **Help rendering dissolved onto the doc lens.** The CLI help screen is now authored as a doc-IR `Doc` and projected through `doc_lens` rather than a bespoke renderer. The help tiers (compact names through expanded group/flag detail) fall out of the doc-IR's effective-tier cascade. Help keeps the full term spelling intact (no lossy flag downcast) and respects Format — the writer strips styles for plain output and emits JSON for `--json` — instead of a one-off ansi toggle. User-visible help layout is materially the same; the authoring DTO (`HelpArg`) and the arg pre-scan (`scan_help_args`) are unchanged.
- **Layers help group leads and stays at minimal verbosity.** Declared Tags render first among the framework help groups and at MINIMAL depth, instead of collapsing with Zoom/Mode/Format when command args lead. Tags are app-declared vocabulary, not universal grammar, so their descriptions show exactly where they are least guessable. Applies in both `run_cli` help and subcommand help.
- **`run_cli` validates `live_delivery` at construction.** Passing a `live_delivery` value outside `{"inplace", "surface"}` now raises `ValueError` at `CliRunner` construction instead of silently degrading to in-place delivery, matching the framework's other declaration-collision checks.
- **Single-write block delivery for `print_block`.** `print_block` and `InPlaceRenderer` now build each frame as one ANSI string (via the shared `render_block_ansi`/`render_row_ansi` builders) and emit it with a single write followed by one flush, instead of flushing per line — removing the mid-frame buffer boundaries that let terminals catch partially drawn frames.
- **Halved `painted.tui` import cost.** `asyncio` (the bulk of the `painted.tui` eager import chain) is now imported lazily inside `Surface.run`, so importing `Surface` — for `TestSurface`, type access, or subclassing — no longer pays for it; only a running event loop does.
- **Scroll-optimization env var renamed to `PAINTED_SCROLL_OPTIM`.** The Surface scroll-optimization toggle now reads the `PAINTED_SCROLL_OPTIM` environment variable, replacing the stale pre-rename `FIDELIS_SCROLL_OPTIM` name.
- **Palette is the single source of theme colors.** Theme presets now compose palette presets instead of redefining colors inline, removing the drift vector that let theme colors desync from the palette (notably the series ramp). A custom `Palette()` with no explicit series now receives the default red/yellow/green/cyan ramp rather than colors derived from its semantic roles.
- **Internal: framework dogfooding and dev infrastructure.** painted's own front door (`src/painted/__main__.py`) was migrated from a hand-rolled multi-command dispatcher to a `run_app` + `AppCommand` table (with `demo` an alias of `demos`), so the CLI drives the same framework painted ships; the README/consumer guide were rewritten to document the disclosure-grammar declaration, the live-delivery ladder, the `run_app` row, and the `painted.cli`/`painted.tui` stability tiers; the test architecture was overhauled by axis into a 10-tier fast-fail gate (arch, lint, smoke, unit, property, appearance, integration, cohesion, outputgen, docs); the pattern demos converged on the `>=` zoom-threshold idiom; the cli→library import allowlist was formalized as `_CLI_SEAMS` with a two-entry "re-layer, never relax" tripwire; and the depth→facet implication law was extracted so non-CLI harnesses and the flag compiler can't diverge. Dev/dogfood/docs only; not shipped in the wheel.

### Removed (breaking)

- **Deep submodule import paths under `painted.views`.** Importing implementation modules directly no longer resolves: `painted.views.profile` and `painted.views.components.{spinner, table, list_view, text_input, data_explorer, sparkline}` were renamed to private underscore-prefixed modules. Public names are unchanged — import them from the `painted.views` facade (the documented path). This closes a latent import-order trap where a public name equal to a submodule filename was permanently shadowed by the module object once anything imported the submodule.
- **`Depth` alias for `Zoom`.** The `Depth` name (an alias of `Zoom`) is removed from `core/fidelity.py` and every export surface. `Zoom` is the one public name for the rung-1 axis, and `ctx.zoom` is the porthole onto `ctx.fidelity` — blessed permanently, two-sidedly clamped to the enum.
- **Density budget flags are opt-in.** `--max-chars`/`--max-lines` now exist only when an app declares `budgets=True` on `run_cli`/`add_cli_args`; the default flipped from `True` to `False`. Previously the flags were added unconditionally yet no `run_cli` app honored them — a dead flag surface. Read `ctx.fidelity.chars`/`ctx.fidelity.lines` after declaring the capability.
- **Generic `--show TAG` escape in the docs CLI.** The docs CLI's `--show TAG` flag is retired in favor of the declaration grammar: `run_doc` enumerates the built doc's node tags into Tag declarations, so a flag like `--rationale` exists exactly on pages that have rationale nodes and appears in each page's Layers help. One spelling per facet. This also deletes the `add_args`/`build_fidelity` pair the docs CLI previously carried.
- **Public help-renderer DTOs and helpers.** `HelpData`, `HelpGroup`, `HelpFlag`, `render_help`, `build_help_data`, and the lossy `help_args_to_flags` bridge are deleted — subsumed by the doc-IR. `HelpData`/`HelpGroup`/`HelpFlag`/`render_help`/`help_args_to_flags` were exported from both `painted.__all__` and `painted.cli.__all__` at v0.1.8, so `from painted import HelpData` no longer resolves; this is allowed because `painted.cli` is the evolving (non-semver-stable) framework surface, but it is a public-name removal. `app_runner` now shares `run_cli`'s `framework_sections`/`command_defs` builders instead of its own parallel help construction. User-visible help behavior is preserved.
- **Bundled static docs site.** The previously bundled `site/` output is no longer tracked; the docs site lives in-repo at `web/` and is regenerated by `./dev panels` rather than shipped.

### Changed (breaking)

- **`big_text` FILLED renders from one 8×8 bitmap font at a selectable density.** The hand-encoded FILLED glyph tables are replaced by a single public-domain IBM PC 8×8 bitmap font plus a density packer, so `size` is a vertical density dial over one font rather than a second font: `size=1` is HALF (8×4 cells, the compact default), `size=2` is FULL (8×8 cells). Glyph width is now a constant 8 cells. Breaking: the `BIG_GLYPHS` value type changed to 8-int tuples and `size=1` output dimensions changed (width `5n-1` → `9n-1`), so downstream fixed layouts may shift. `BIG_GLYPHS` and `render_big` are in the semver-stable `painted.views.__all__`. OUTLINE is unchanged.

### Fixed

- **InPlaceRenderer flicker and blank-phase tearing.** `InPlaceRenderer` now emits each frame as one atomic write wrapped in DEC 2026 synchronized-output markers, overwrites rows in place with erase-to-EOL (CSI 0K) instead of blanking the whole region first, and row-diffs same-height frames so only changed rows are rewritten (unchanged rows become cursor hops). This eliminates the flicker and torn partial frames seen when a window is backgrounded; terminals that ignore the sync markers degrade cleanly.
- **Frame-time-compensated Surface pacing.** The Surface run loop slept a full frame period after each blocking render, so animating apps ran at roughly render_time + period (~23fps under a 30fps cap). Pacing is now the pure function `frame_sleep(elapsed, fps_cap, active=)`, which sleeps only the remainder of the frame period, floored at `MIN_YIELD` — restoring the capped frame rate.
- **Surface restores the terminal when `run()` setup fails.** `Surface.run` entered the alt screen and hid the cursor before its try/finally, so an exception during sizing, user `layout()`, or signal-handler setup left the terminal wedged. Setup now runs inside the try, and the finally guards SIGWINCH removal for the not-yet-installed case, so the terminal is always restored.
- **Surface-path delivery errors honor the exit-code contract.** A delivery-level exception escaping the alt-screen `StreamSurface` path (terminal setup or sizing failure) is now translated to a stderr message and exit code 1 instead of leaking a traceback past `run_cli`'s documented `int` return contract. User fetch and render errors continue to map to exit 1 and 2 respectively.
- **Pause key in surface live delivery.** The old hand-rolled streaming handlers bound pause to `"space"` while the keyboard reports the spacebar as `" "`, so pause never fired. Converging the live tiers onto `StreamSurface` fixed it — the spacebar now toggles pause, which stops consuming the stream (nearly free).
- **`render_html` resolves named colors through painted's own color table.** `render_html` now maps a named color (e.g. `"red"`) to its painted ANSI-index RGB rather than passing the CSS keyword through, so HTML output matches what painted renders in the terminal (CSS keyword `"red"` is `#FF0000` but painted red is not).
- **Normal ANSI colors brightened for dark-background legibility.** The six normal ANSI colors (1–6) move from classic VGA half-intensity `0x80` to `0xC0` (192), matching modern terminals; normal red was below the WCAG 3:1 contrast floor on dark backgrounds. The RGB table is dual-use, so this brightens `render_html` and int-color display output and also shifts the truecolor-to-16 downsampling anchors. It stops at 192 (not xterm's 205) to avoid crushing dark midtones to black.
- **NORD and MONO flame colors.** `flame_lens` under NORD now renders in color: the old path stringified a numeric role fg (e.g. `"174"`), which is neither a named nor hex color, so the writer emitted nothing. MONO flame is now an honest modifier-only cycle instead of a warm-colored fallback. Both follow from routing flame through `Palette.series`.
- **Figure caption width.** A doc/help `Figure`'s caption now renders at the available width rather than the embedded block's (often narrower) width, so captions word-wrap to the full column instead of clipping to the figure.
- **Width overflow in record composers and lenses.** Record composers no longer overflow: `record_line_composed` previously prepended an unbudgeted 2-column attention marker (so a composed record exceeded its width despite an exact leaf) — the marker is now reserved into the inner width, evaluated exactly once via a threaded score, and the prior double evaluation could reserve marker width for one score and render another. SUMMARY/DETAILED record lines pad to full width instead of under-filling, FULL word-wraps long values instead of overflowing, empty `record_timeline`/`record_map` honor width instead of returning a natural-width "(no records)", `flame_lens` segment widths fit to width (a `val<=0` last segment previously lost the remainder), and the `shape_lens` list prefix is clamped into the budget.
- **Internal: invariant guards and dev-suite fixes.** An invariant audit fed generalized static guards (runtime imports restricted to stdlib/painted/`wcwidth`, every state dataclass asserted frozen — `CellWrite` now frozen, `AppCommand.help_args`/`IconSet.spinner` tuple-coerced) plus diff-render/stable-surface regression tests with ambient-state de-flaking; the appearance fixture now fails on a bootstrapped first-write snapshot; and the disk example liveness smoke renders synthetic volumes instead of walking the real filesystem (fixing a hang). Internal test/dev infrastructure only.
